# Redis 利用中继说明（mdut-relay）

## 背景

在利用 Redis 主从复制加载恶意 Module 时，目标 Redis 服务器需要主动向"主节点"发起连接。如果目标处于内网或通过 SOCKS5 代理访问，目标无法直接回连到本地监听端口，导致利用失败。

**mdut-relay** 是一个部署在公网 VPS 上的轻量级 TCP 双向转发工具，用于解决这个回连问题。

## 架构图

```
[MDUT 本地] <──── 端口 21000 ────> [VPS: mdut-relay] <──── 端口 21001 ────> [目标 Redis]
```

- 端口 **21000**：MDUT 客户端连接中继的控制端口
- 端口 **21001**：目标 Redis 服务器回连中继的端口

## 准备工作

1. 准备一台有公网 IP 的 VPS
2. 开放防火墙端口 `21000` 和 `21001`（TCP）
3. 从 [mdut-relay releases](https://github.com/Ch1ngg/mdut-relay/releases) 下载对应平台的二进制

## 部署步骤

### 第一步：在 VPS 上启动中继

```bash
# 使用默认端口（21000 控制端，21001 目标端）
./mdut-relay

# 自定义端口
./mdut-relay -cp 21000 -tp 21001
```

参数说明：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-cp` | MDUT 客户端连接端口（Control Port） | `21000` |
| `-tp` | 目标 Redis 回连端口（Target Port） | `21001` |

启动后中继会持续监听，等待两端同时连接后自动建立双向转发通道。连接空闲超过 15 秒自动断开，防止占用。

### 第二步：在 MDUT 中配置中继

在 MDUT 的 Redis 利用面板中，将主从复制（Rogue Server）模式设置为中继模式，填写：

- **中继地址**：VPS 公网 IP
- **控制端口**：`21000`（与 `-cp` 一致）
- **目标回连端口**：`21001`（与 `-tp` 一致）

### 第三步：执行利用

配置完成后，点击「部署 Module」，MDUT 会：

1. 通知目标 Redis 以从节点模式连接 `VPS:21001`
2. 本地 MDUT 同时连接 `VPS:21000`
3. 中继在两端都连接后建立透明转发通道
4. Module 文件通过通道传输到目标并加载

## 使用场景

| 场景 | 是否需要中继 |
|------|------------|
| 目标 Redis 可直接访问，本地有公网 IP | ❌ 不需要 |
| 目标通过 SOCKS5 代理访问，本地无公网 IP | ✅ 需要 |
| 目标在内网，本地无公网 IP | ✅ 需要 |
| 目标可直接访问，本地有公网 IP 但被防火墙拦截 | ✅ 需要 |

## 注意事项

- 中继本身不保存任何数据，仅做透明转发
- 每次利用完成后建议重启中继，避免旧连接残留
- VPS 的 21000/21001 端口在利用完成后建议关闭
